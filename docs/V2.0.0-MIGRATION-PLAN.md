## 1. Executive Summary & Objective

In **Version 1.0.0**, Why Did AI Do That? (WDAIDT) achieved a robust, fully verified baseline for real-time ChatGPT diagnostic analysis. However, V1.0.0 requires a dual-process architecture:
1. A **Manifest V3 Chrome Extension** (`extension/`) for DOM interaction and user interface.
2. A **Local Python FastAPI Server** (`backend/`) running on `http://localhost:8000` to manage prompt composition, call the Google GenAI SDK, and validate schemas using Pydantic.

While effective for developers, this prerequisite presents severe friction for everyday users: installing Python 3.10+, creating virtual environments, installing dependencies via `pip`, configuring `.env` files, and starting a terminal process before launching the browser.

### The V2.0.0 Goal
**Convert WDAIDT into a 100% self-contained Chrome extension** that connects directly to the Google Gemini API using a user-provided API key stored securely in `chrome.storage.local`.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        WDAIDT V1.0.0 ARCHITECTURE                      │
│                                                                        │
│   ChatGPT Tab  ──►  Extension Side Panel  ──►  Local FastAPI Backend  │
│   (DOM Scraping)     (app.js Controller)       (Python 8000 / Pydantic)│
│                                                          │             │
│                                                          ▼             │
│                                                    Gemini API          │
└────────────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────────────┐
│                        WDAIDT V2.0.0 ARCHITECTURE                      │
│                                                                        │
│   ChatGPT Tab  ──►  Extension Side Panel  ─────────►   Gemini API      │
│   (DOM Scraping)     (Self-Contained Extension)   (Direct HTTPS Fetch) │
│                      ├── Prompt Construction                           │
│                      ├── Schema Validation                             │
│                      ├── Key Storage & Settings                        │
│                      └── Hermetic Mock Engine                          │
└────────────────────────────────────────────────────────────────────────┘
```

The user will install the extension, paste their Gemini API key into the Settings drawer (or toggle Mock Mode for zero-key exploration), and immediately begin analyzing interactions. No Python, no terminal, and no local server required.

## 4. Proposed V2 Extension-Only Architecture

To avoid unnecessary abstractions, build steps, or external bundlers, V2.0.0 maintains the existing modular vanilla JavaScript architecture. Non-module scripts share standard global namespaces (`globalThis.WDAIDT_*`), with CommonJS exports (`module.exports`) conditionally provided for headless Node.js testing.

### 4.1 Module Structure

```

├── manifest.json
├── assets/
│   ├── icon16.png
│   ├── icon48.png
│   └── icon128.png
└── src/
    ├── background/
    │   └── service-worker.js         # Side panel routing & installation defaults
    ├── content/
    │   └── chatgpt.js                # DOM capture & streaming watcher (unchanged)
    ├── shared/
    │   ├── config.js                 # Configuration, limits, model presets
    │   ├── messages.js               # Cross-component message contracts & stale guard
    │   ├── prompts.js                # [NEW] Authoritative prompt composition
```

## 5. Gemini API Integration & API-Key Handling

### 5.1 Official Gemini REST Specification

The integration connects directly to the Google Generative Language REST API (`v1beta`):

* **Endpoint:** `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
* **Default Model:** `gemini-2.5-flash` (with automatic fallback to `gemini-1.5-flash` or `gemini-2.5-flash-lite`)
* **Authentication:** HTTP Request Header `x-goog-api-key: {API_KEY}` (avoids exposing API keys in request URLs or query strings)
* **Request Payload Structure:**
  ```json
  {
    "systemInstruction": {
      "parts": [
        {
          "text": "<composed authoritative system prompt + style & depth guidance>"
        }
      ]
    },
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "<XML-isolated conversation history + current interaction>"
          }
        ]
      }
    ],
    "generationConfig": {
      "temperature": 0.2,
      "responseMimeType": "application/json"
    }
  }
  ```
* **Response Traversal:**
  Extracted text is parsed from:
  `response.candidates[0].content.parts[0].text`
* **HTTP Error Code Mapping:**
  * `400 INVALID_ARGUMENT`: Invalid model parameter or malformed request payload.
  * `401 / 403 PERMISSION_DENIED / API_KEY_INVALID`: Invalid or inactive Gemini API key. Surfaces actionable prompt: *"Invalid Gemini API key. Check your key in Settings."*
  * `429 RESOURCE_EXHAUSTED`: Rate limit or quota exceeded. Surfaces: *"Gemini quota exceeded or rate limited. Please wait a moment."*
  * `503 / 500 UNAVAILABLE / INTERNAL`: Model overloaded. Automatically retries fallback candidate; if all fail, surfaces clean retryable error.
  * `AbortError` (Client Timeout >= 20s): Surfaces: *"Gemini took too long (>20s)."*

### 5.2 Required Chrome Permissions & Manifest Changes

* **Existing Permissions (Retained):**
  * `"sidePanel"`: Side panel presentation.
  * `"storage"`: Local persistent settings and API key storage.
  * `"activeTab"` & `"scripting"`: Reading visible DOM in ChatGPT tab.
* **Host Permissions:**
  * Existing: `"https://chat.openai.com/*"`, `"https://chatgpt.com/*"`
  * **Added in V2:** `"https://generativelanguage.googleapis.com/*"`
* **Why this is strictly minimal:**
  * Does not request `<all_urls>`.
  * Does not request `webRequest`, `cookies`, `identity`, or broad origins.
  * Restricts outbound network traffic strictly to Google's official Gemini endpoint.

## 7. Security, Privacy & Data Minimization

### 7.1 API Key Security Boundary

1. **Client-Side Storage Isolation:**
   The user's API key is stored exclusively in `chrome.storage.local`. In Chrome's architecture, `chrome.storage.local` is encrypted at rest within the user's browser profile directory and is never synchronized to Chrome Sync or exposed to web pages.
2. **No Shared Master Key:**
   WDAIDT does not ship with a hardcoded or bundled API key. Every user supplies their own personal key generated through Google AI Studio.
3. **No Intermediary Proxies:**
   No telemetry servers, analytics collectors, or third-party proxies exist. Requests travel directly from the user's browser to `https://generativelanguage.googleapis.com`.
4. **Header-Based Authentication:**
   The API key is transmitted via the `x-goog-api-key` HTTP header, ensuring it does not appear in URL query strings, server access logs, or browser navigation history.
5. **Physical / Admin Access Disclosure:**
   As with any client-side browser extension, an adversary with physical or administrative access to the user's operating system user profile could inspect local storage. Users requiring maximum security should utilize API keys with configured quota limits in Google AI Studio.

### 7.2 Data Transmission & Minimization

* **What is sent to Google:**
  Only when live analysis is performed (and Mock Mode is OFF), the active ChatGPT user prompt, assistant response, and preceding conversation turns within the user-configured Context Window are sent over HTTPS to Google.
* **Minimization Controls:**
  * **Context Window Selector:** Users who wish to limit conversation exposure can set the context window to `0 previous exchanges` (analyzing only the current prompt/response) or adjust between 3, 5, or 10 turns.
  * **Character Truncation:** Payload limits strictly cap transmitted content at 8,000 characters for prompts, 20,000 characters for responses, and 30,000 characters for cumulative context.
  * **Passive XML Isolation:** Untrusted conversation text is wrapped inside `<CURRENT_INTERACTION>` and `<CONVERSATION_HISTORY>` tags with strict system prompt boundaries to prevent prompt injection.

## 11. Risks, Open Questions & Recommended Decisions

| Risk / Question | Impact | Recommended Decision |
| :--- | :--- | :--- |
| **1. Gemini Model Availability** | Hardcoding a retired model could cause 404 errors. | Default to `gemini-2.5-flash`. Implement runtime fallback list (`gemini-2.5-flash`, `gemini-1.5-flash`, `gemini-2.5-flash-lite`) in `gemini-client.js`. |
| **2. API Key Leakage via URLs** | Putting `?key=` in the URL exposes keys to browser history and proxy logs. | Use the `x-goog-api-key: {KEY}` HTTP header exclusively for all REST calls. |
| **3. Schema Validation without Pydantic** | Malformed LLM output could break block rendering. | Implement a dedicated `validator.js` that checks structure and normalizes fields (e.g. guaranteeing `prompt` and `content` on `next_prompt`). Furthermore, existing `app.js` block renderers already include graceful fallbacks (`renderBlock` falls back to paragraph for unknown types). |
| **4. Rate Limits on Free Tier** | Free Gemini API keys have rate limits (e.g. 15 RPM). | Gracefully catch HTTP 429 and present a friendly, informative message in the side panel status line with a clear Retry button. |
| **5. Large History / Token Limits** | Long conversations could exceed model token limits. | Preserve the existing context budgeting algorithm in `app.js` (capping context at 30,000 characters and dropping older exchanges first). |
