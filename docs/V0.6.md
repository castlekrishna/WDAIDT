# V0.6 — Adaptive Analysis Architecture, Dynamic Document Renderer & Quality Overhaul

## Overview

WDAIDT V0.6 replaces the legacy fixed four-field analysis format (`why`, `influences`, `assumptions`, `what_could_change`) with an **Adaptive Analysis Architecture** and an **Analysis Quality Engine**.

Instead of coercing every interaction into four rigid categories or merely summarizing what the user has already read, Google's Gemini models dynamically diagnose the prompt-response interaction, identify missing constraints and omitted trade-offs, and supply actionable next steps (including ready-to-use follow-up prompts) rendered dynamically by the extension side panel.

---

## 1. Fundamental Product Principle

> **WDAIDT must NOT explain to users what an AI response already tells them.**
> The user has already read the response. Repeating or summarizing its contents in different words provides little value.
> WDAIDT must instead help users understand:
> 1. What caused the AI to respond in this particular way.
> 2. What important information, clarification, constraint, or reasoning was missing.
> 3. Whether the response has a meaningful shortcoming relative to the user's apparent goal.
> 4. What could be improved in the interaction or in the response.
> 5. What the user should do next to obtain a more useful result.
> 
> **The primary goal is to improve the user's NEXT interaction with AI.**

## 2. Document-Based API Contract

### Request: `POST /analyze`

```json
{
  "prompt": "Should I learn Python or Java for AI?",
  "response": "Python is generally recommended because of its AI ecosystem.",
  "request_id": "req-123",
  "response_style": "Professional and direct",
  "custom_instructions": "Focus on developer tooling trade-offs",
  "analysis_depth": "Balanced"
}
```

- `prompt` (`str`, required, max 8,000 chars): Captured user query.
- `response` (`str`, required, max 20,000 chars): Captured ChatGPT assistant reply.
- `request_id` (`str`, optional): Client-generated UUID echoed back for stale-result protection.
- `response_style` (`str`, optional): Preset tone or `"Custom instructions"`.
- `custom_instructions` (`str`, optional, max 1,000 chars): Custom style guidance provided by user.
- `analysis_depth` (`str`, optional): `"Brief"`, `"Balanced"`, or `"Detailed"`.

### Response: 200 OK

```json
{
  "request_id": "req-123",
  "analysis": {
    "title": "Diagnosis: Underspecified Learning Scope",
    "blocks": [
      {
        "type": "paragraph",
        "content": "The AI appears to have adopted a broad, generalized interpretation because the prompt lacks specific constraints (such as deployment environment or prior background)."
      },
      {
        "type": "heading",
        "level": 2,
        "content": "Diagnostic Findings"
      },
      {
        "type": "list",
        "style": "unordered",
        "items": [
          "Missing constraints: Specific scale or existing tech stack boundaries were unstated, prompting the AI to assume generic defaults.",
          "Omitted trade-offs: The answer focuses on the most popular path without detailing migration friction or maintenance overhead."
        ]
      },
      {
        "type": "next_prompt",
        "title": "Suggested Next Prompt",
        "prompt": "Considering my background as a backend Python engineer, what are the primary trade-offs and alternative approaches when working with strict performance constraints?"
      }
    ]
  }
}
```

## 3. Supported Content Blocks

V0.6 implements an extensible discriminated union schema (`type` discriminator) validated by Pydantic on the backend and safely rendered via DOM elements on the frontend:

1. **Heading** (`heading`): `level` (1-6), `content`.
2. **Paragraph** (`paragraph`): `content` preserving whitespace.
3. **List** (`list`): `style` (`"ordered"` / `"unordered"`), `items`.
4. **Code** (`code`): `language`, `content`, monospace block with copy button.
5. **Quote** (`quote`): `content`, blockquote with accent border.
6. **Table** (`table`): `headers`, `rows`, responsive horizontal scroll wrapper.
7. **Callout** (`callout`): `variant` (`info`, `warning`, `caution`, `tip`, `note`, `important`), `title`, `content`.
8. **Next Prompt** (`next_prompt`): `prompt`, `title`. Action-oriented follow-up card featuring a one-click **Copy prompt** button and one-click select.
9. **Divider** (`divider`): `<hr class="block-divider">`.

## 4. Master Prompt & Runtime Composition

The backend maintains **one authoritative master analysis prompt** in [`backend/app/analysis/prompts.py`](file:///d:/devPost/WDAIDT/backend/app/analysis/prompts.py).

- **Anti-Narration Prohibition**: Explicitly forbids generic narration:
  - *"The AI used a friendly tone."*
  - *"The AI provided a detailed explanation."*
  - *"The response contains several recommendations."*
  - *"The AI structured its answer into sections."*
  - *"The response ends with a call to action."*
- **Epistemic Boundaries**: Strictly hedges observations ("The response appears to...", "Seems to prioritize..."). It never claims direct access to ChatGPT's private weights or hidden chain of thought.
- **Fairness to the Response**: Acknowledges satisfactory answers (e.g. simple factual lookups) without manufacturing artificial flaws.
- **Data vs. Instructions**: Treats captured text strictly as passive data, mitigating prompt injection.
- **Runtime Composition**: At request time, `compose_system_instructions()` weaves:
  1. Master system prompt.
  2. Selected Response Style guidance or Custom instructions.
  3. Selected Analysis Depth instructions.

## 5. Response Style & Depth Settings

The extension side panel features a dedicated Settings interface (`#settingsCard`) accessible via a gear icon in the topbar:

### Response Style Presets
1. **Friendly and conversational**: Warm, approachable, natural tone.
2. **Lighthearted and witty**: Clever and engaging with subtle wit.
3. **Casual and natural**: Relaxed, conversational, everyday language.
4. **Professional and direct** (Default): Concise, objective, action-oriented.
5. **Formal and precise**: Rigorous terminology and structured phrasing.
6. **Academic and analytical**: Systematic breakdown from a scholarly perspective.
7. **Custom instructions**: Displays a dedicated textarea for custom user prompts.

### Analysis Depth Presets
- **Brief**: High-level diagnosis and primary next action (1-2 blocks).
- **Balanced** (Default): Standard balanced diagnosis of omissions and suggested next prompt (3-5 blocks).
- **Detailed**: Comprehensive breakdown covering nuances, edge cases, trade-offs, and verification prompts.

### Persistence
Settings persist across browser sessions using `chrome.storage.local`:
- `wdaidt_response_style`
- `wdaidt_custom_instructions`
- `wdaidt_analysis_depth`

## 7. Sidebar Space Optimization & Capture Integrity Audit

### Overview
The sidebar layout is optimized to prioritize the dynamic analysis document, and the captured interaction pipeline is audited to ensure data integrity and full-text inspection without premature truncation.

### Key Enhancements
1. **Collapsed-by-Default Accordion**:
   - The Captured Interaction section (`#captureCard`) is collapsed upon opening the side panel, freeing up vertical space for the analysis document.
   - An interactive header (`#captureAccordionToggle`) with an animated indicator chevron (`▼` when collapsed, `▲` when expanded) allows instant toggling.
   - A status pill badge (`#captureStatusBadge`) indicates when an interaction is captured even while the accordion is collapsed.
   - Fully keyboard-accessible via `Enter` and `Space`, communicating state through `aria-expanded`, `aria-controls="captureAccordionContent"`, and `role="button"`.
   - Expansion state is preserved during new analysis runs (starting, completing, or failing an analysis does not automatically expand or toggle the drawer).

2. **Full-Text Independently Scrollable Container**:
   - Replaced previous 600-character truncation (`PREVIEW_CHARS`) in the expanded view with complete text display.
   - Single bounded container (`max-height: 240px; overflow-y: auto; overscroll-behavior-y: contain`) ensures smooth vertical scrolling through both prompt and response without double-nested scrollbars or unintended outer sidebar scrolling.
   - Wrapping rules (`white-space: pre-wrap; word-break: break-word; overflow-wrap: anywhere;`) prevent overflow from long strings.

3. **Capture Integrity Audit**:
   - Traced the complete data pipeline from DOM extraction through frontend state and payload construction to the backend.
   - Diagnosed the cause of the ellipsis ("Lists, tuple...") as UI preview truncation in `app.js` (`s.length > limit ? s.slice(0, limit) + '…' : s`).
   - Aligned the displayed text with backend payload limits (`MAX_PROMPT_CHARS = 8000`, `MAX_RESPONSE_CHARS = 20000`) via `trimForBackend`.
   - Verified that the backend receives the complete prompt and response and that the text displayed in the expanded drawer is 100% identical to the request payload.

## 8. Known Limitations

- V0.6 focuses on single-turn interaction analysis. Multi-turn conversation context is planned for future milestones.
- Live Gemini API calls require a valid `GEMINI_API_KEY` configured in `backend/.env`. When testing offline, `MOCK_ANALYSIS=true` provides realistic diagnostic document responses adhering to the V0.6 quality standard.
