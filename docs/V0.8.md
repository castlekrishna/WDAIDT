# V0.8 — Stabilization & Reliability Release

## Overview

WDAIDT V0.8 is a comprehensive stabilization and reliability release. Its purpose is to audit, harden, and verify the established functionality of **Why Did AI Do That? (WDAIDT)** across both the Chrome extension (Manifest V3) and the FastAPI backend service before final release preparation.

V0.8 does not add new AI providers, database models, or UI redesigns. Instead, it systematically verifies all seven critical operational areas, addresses regression coverage gaps, confirms end-to-end integration contracts, validates live Gemini API behavior, and establishes a regression-proof baseline of **162 passing automated tests** (up from the 142 baseline).

---

## 1. Verification Audit by Area

### A. ChatGPT Conversation Capture
- **Target Component**: `extension/src/content/chatgpt.js`
- **Verified Behaviors**:
  - Latest completed user prompt and assistant response are captured accurately across 6 tiered strategies (`role-attributes`, `message-id`, `conversation-turns`, `articles`, `modern-turns`, `content-blocks`).
  - Multi-turn conversation extraction reliably pairs subsequent user prompts with assistant responses, even when users submit brief prompts (e.g. "hi") or multiline queries.
  - Regenerated assistant responses are handled correctly: all candidate assistant drafts within a turn are collected and the latest settled draft is paired with the turn's prompt.
  - Streaming protection: active streaming assistant turns (empty or updating DOM text nodes) are never treated as complete; honest partial status (`RESPONSE_PENDING` / `paired: false`) is returned without initiating premature analysis.
  - Non-conversation elements (composer forms, sidebar histories, tooltips, feedback surveys, drag-and-drop live announcers, and footer disclaimers) are strictly excluded from turn extraction.
  - Single-page application (SPA) client-side navigation reliably re-binds to the active conversation container without stale bleed from prior threads.
- **Verification Status**: ✅ Verified without breaking changes.

### B. Multi-Context Analysis
- **Target Components**: `extension/src/content/chatgpt.js`, `extension/src/sidepanel/app.js`, `backend/app/analysis/prompts.py`, `backend/app/api/analyze.py`
- **Verified Behaviors**:
  - Context window settings (`0`, `3`, `5`, `10` previous exchanges; default: `5`) are persisted in `chrome.storage.local` and fall back gracefully to default on invalid input.
  - **Context window represents a maximum, not a minimum requirement**: analysis proceeds cleanly whether 0, 1, 2, 5, or 12 prior turns exist, without blocking, throwing errors, or injecting synthetic turns.
  - The current prompt and response are always evaluated separately and never duplicated inside the historical context.
  - Historical exchanges maintain strict chronological order (oldest to newest).
  - Context character budgets (`MAX_CONTEXT_TOTAL_CHARS = 30000` client budget / `40000` backend acceptance limit; `MAX_CONTEXT_EXCHANGES = 20`) are strictly enforced, discarding older complete exchanges first while keeping recent turns intact and never producing partial exchange fragments.
  - The side panel Captured Interaction header displays the actual transmitted context count (`"Current exchange only"`, `"Context: 1 previous exchange"`, `"Context: N previous exchanges"`).
- **Verification Status**: ✅ Verified; robust prompt builder handling for context objects and dicts implemented.

### C. Extension-to-Backend Integration
- **Target Components**: `extension/src/sidepanel/app.js`, `extension/src/shared/messages.js`, `extension/src/shared/config.js`, `extension/src/background/service-worker.js`
- **Verified Behaviors**:
  - Manual **Why?** analysis triggers capture, sends normalized payload to `POST /analyze`, and renders the dynamic document.
  - Auto Analyze stream-completion watcher debounces settled assistant responses and triggers automatic analysis only when the toggle is enabled (`ON`).
  - Auto toggle state is persisted in `chrome.storage.local` and broadcast across open ChatGPT tabs via runtime messages.
  - Request ID propagation ensures stale-result protection: in close-succession requests, responses matching superseded `request_id`s are dropped silently.
  - Transmission of tone presets (`response_style`), custom instructions, analysis depth (`analysis_depth`), and context history conforms exactly to API agreement.
  - Error states (HTTP 413, 422, 429, 502, 504, fetch abort timeout, network disconnect) surface user-friendly guidance in the Obsidian error card and display the **Retry** action.
- **Verification Status**: ✅ Verified; 11 new integration unit tests added in `tests/extension/integration.test.js`.

### D. Backend Reliability
- **Target Components**: `backend/app/main.py`, `backend/app/api/analyze.py`, `backend/app/analysis/analyzer.py`, `backend/app/models/analysis.py`, `backend/app/models/exceptions.py`
- **Verified Behaviors**:
  - `GET /health` returns `{"status":"ok"}` with 200 OK.
  - Request size boundaries enforced: prompt (max 8,000 chars) and response (max 20,000 chars) return 413 `PAYLOAD_TOO_LARGE` if exceeded.
  - Empty or whitespace-only prompts/responses return 422 `INVALID_REQUEST`.
  - Missing `GEMINI_API_KEY` returns an actionable 502 `AI_PROVIDER_ERROR` explaining setup options, never a silent fake mock.
  - Mock mode is strictly opt-in via `MOCK_ANALYSIS=true`.
  - Unmapped URLs and unsupported HTTP methods conform to the standardized error envelope (`{"error": {"code": "NOT_FOUND" / "METHOD_NOT_ALLOWED", "message": "..."}}`).
  - Backward compatibility: requests omitting `context` or passing `context: []` or `context: null` execute flawlessly.
- **Verification Status**: ✅ Verified; 9 new backend regression tests added in `tests/backend/test_analyze.py`.

### E. Analysis Quality & Epistemic Safety
- **Target Components**: `backend/app/analysis/prompts.py`, `backend/app/analysis/analyzer.py`
- **Verified Behaviors**:
  - Anti-narration: Master prompt explicitly prohibits repeating the user's prompt or narrating/summarizing the AI response.
  - Epistemic modesty: Explanations communicate plausible diagnostic reasons grounded in visible evidence without claiming direct access to hidden model activations or private chains of thought.
  - Satisfactory response handling: High-quality factual or creative answers are validated without manufacturing arbitrary criticism.
  - Multi-context diagnostic detection:
    - Identifies when an AI response ignores an explicit constraint established earlier in the conversation (e.g. standard library requirement).
    - Identifies when an AI response contradicts an environment clarification (e.g. Windows PowerShell vs Linux bash).
    - Disambiguates an ambiguous follow-up whose antecedent depends on conversation history (e.g. "rewrite it with recursion").
    - Diagnoses omitted trade-offs and generates actionable, ready-to-use follow-up prompts (`next_prompt`).
  - Prompt injection isolation: Untrusted user input and history demarcated within `<CONVERSATION_HISTORY>` and `<CURRENT_INTERACTION>` XML delimiters and treated strictly as passive diagnostic data.
- **Verification Status**: ✅ Verified; comprehensive test cases added to backend test suite.

### F. UI, Settings, and Error States
- **Target Components**: `extension/src/sidepanel/index.html`, `extension/src/sidepanel/styles.css`, `extension/src/sidepanel/app.js`
- **Verified Behaviors**:
  - Pitch-black (`#000000`) Obsidian editor theme with high-contrast text and thin custom scrollbars.
  - Settings panel drawer with response styles (Friendly, Witty, Casual, Professional, Formal, Academic, Custom) and depths (Brief, Balanced, Detailed) persists across extension reloads.
  - Captured Interaction accordion is collapsed by default to preserve vertical space; independently scrollable when expanded without text ellipsis truncation.
  - Full keyboard accessibility: `Enter` and `Space` toggle controls, `:focus-visible` styling, and appropriate ARIA attributes.
  - One-click copy buttons for code snippets, suggested next prompts, and full markdown document export.
  - Safe rendering: all 9 block types (`heading`, `paragraph`, `list`, `code`, `quote`, `table`, `callout`, `divider`, `next_prompt`) use `textContent` DOM nodes; zero `innerHTML` usage prevents XSS.
- **Verification Status**: ✅ Verified without changes to established visual styling.

### G. Privacy and Security
- **Verified Behaviors**:
  - Gemini API credentials remain strictly on the backend (`backend/.env`); `.env` is ignored by Git.
  - Prompts and responses are processed in-memory for analysis and are never persisted in databases or written to application logs (lengths-only structured logging).
  - CORS configuration explicitly disables credentials and supports `chrome-extension://` callers.
  - User-supplied conversation content is treated as untrusted data at all layers.
- **Verification Status**: ✅ Verified.

## 2. Actual Changes in V0.8

1. **Manifest and Content Script Version Alignment**:
   - `extension/manifest.json`: bumped version to `0.8.0` with updated description.
   - `extension/src/content/chatgpt.js`: updated `VERSION = '0.8.0'`.
   - `backend/app/api/analyze.py`: updated module documentation to V0.8.
   - `extension/src/sidepanel/app.js`: updated header documentation to V0.8.

2. **Resilient Context Handling in Prompt Builder**:
   - `backend/app/analysis/prompts.py`: `build_analysis_user_prompt` now safely extracts `prompt` and `response` attributes whether `context` contains `ContextExchange` objects or standard dictionaries (`getattr(ex, "prompt", None) or ex.get("prompt")`).

3. **Extension App Module Exports for Automated Testing**:
   - `extension/src/sidepanel/app.js`: exported `postAnalyze`, `analyzeCapture`, `newRequestId`, `isStale`, `getLatestRequestId`, `setLatestRequestId`, `showError`, `clearResult`, `renderResult`, `initAutoToggle`, and `notifyTabsAuto` within the Node test environment export block.

4. **New Integration Test Suite**:
   - `tests/extension/integration.test.js`: added 11 unit tests verifying payload transmission, custom instruction gating, HTTP error status mappings (413, 429, 422, 502, network failure, timeout), stale result dropping, error card UI transitions, and Auto Analyze toggle messaging.

5. **New Backend Reliability & Quality Regression Tests**:
   - `tests/backend/test_analyze.py`: added 9 unit tests verifying `context: null` compatibility, `custom_instructions` length validation (422), 404 `NOT_FOUND` and 405 `METHOD_NOT_ALLOWED` error envelopes, overlooked user constraints in multi-context, contradicted clarifications in multi-context, ambiguous follow-ups, omitted trade-offs, and prompt injection isolation.

## 5. Remaining Limitations & Manual Checks

1. **Manual Extension Reload in Browser**:
   - Automated test runners simulate DOM and Chrome extension runtime APIs. Manual verification of the unpacked extension in Chrome against `https://chatgpt.com` is recommended to verify live rendering in newly rolled out OpenAI DOM layout variants.
2. **Network Dependency for Live Analysis**:
   - When running without mock mode (`MOCK_ANALYSIS=false`), an active internet connection and valid `GEMINI_API_KEY` are required.
