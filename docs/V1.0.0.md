## 1. Release Purpose and Scope

**Why Did AI Do That? (WDAIDT)** reaches its first stable release, `v1.0.0`. This milestone freezes the product scope, hardens all runtime components, verifies the complete automated test baseline across the Chrome Extension and FastAPI backend, synchronizes canonical versioning across all codebase metadata and documentation, and prepares verified release distribution assets.

### Frozen Scope Adherence
As a stabilization and release-preparation milestone, WDAIDT V1.0.0 strictly preserves proven functionality and contracts without adding unnecessary features, databases, telemetry, or external hosting:
- **Two Separately Runnable Components**: Preserves the local-server architecture consisting of the Chrome Extension (`extension/`) and the Local FastAPI Backend (`backend/`).
- **Obsidian Theme Integrity**: Retains the pitch-black background (`#000000`), subtle cards (`#111111`), borders (`#303030`), and status-only semantic accent color system.
- **Epistemic Modesty**: Explanations remain grounded in visible conversation evidence, avoiding claims about unobservable internal model weights or hidden chains of thought.
- **Privacy First**: Ephemeral in-memory execution, lengths-only structured logging, and zero tracking.

## 2. Architecture and Component Responsibilities

The system maintains a clear, decoupled division of responsibilities:

```
[ ChatGPT Web Interface (chatgpt.com / chat.openai.com) ]
                          │
            DOM Extraction & Stream Watcher
                          ▼
[ Chrome Extension: extension/ (Manifest V3) ]
  ├── Content Script (chatgpt.js): 6-strategy DOM capture, Shadow DOM traversal, multi-turn history
  ├── Background Service Worker (service-worker.js): Side panel lifecycle & icon click routing
  ├── Side Panel Controller (app.js): Controls, settings state, safe DOM rendering (textContent only)
  └── Shared Contracts (messages.js, config.js): Actionable error mapping & stale-result guards
                          │
             HTTP POST /analyze (JSON)
                          ▼
[ Local FastAPI Backend: backend/ (http://localhost:8000) ]
  ├── API Layer (main.py, analyze.py): /health & /analyze, Pydantic validation, payload limits
  ├── Data Models (analysis.py, exceptions.py): AnalysisDocument with 9 discriminated union blocks
  ├── Prompt Composition (prompts.py): Master diagnostic prompt, passive XML data isolation
  └── Analysis Engine (analyzer.py): Gemini client (gemini-3.5-flash-lite) + Zero-config Mock Mode
```

### Component Boundaries
- **Extension Content Script (`extension/src/content/chatgpt.js`)**: Captures only. Never initiates HTTP requests to the backend or external AI APIs.
- **Extension Side Panel (`extension/src/sidepanel/app.js`)**: Coordinates user controls, requests capture from the content script, transmits requests to `http://localhost:8000/analyze`, and renders the returned document using DOM element construction without `innerHTML`.
- **FastAPI Backend (`backend/app/main.py`)**: Runs locally on `http://localhost:8000`. Validates request constraints (prompt <= 8k chars, response <= 20k chars, context <= 40k chars / 20 exchanges), enforces CORS for extension origins, isolates untrusted text inside `<CURRENT_INTERACTION>` and `<CONVERSATION_HISTORY>` XML delimiters, and invokes Google Gemini or Mock Mode.

## 5. Local Server Startup and Health Verification

The backend is installed and executed independently from `backend/`:

### Windows PowerShell Setup
```powershell
# 1. Create and activate virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 2. Install dependencies
pip install -r backend/requirements.txt

# 3. Configure environment
Copy-Item backend/.env.example backend/.env

# 4. Start the FastAPI backend
python -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

### Linux / macOS Setup
```bash
# 1. Create and activate virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 2. Install dependencies
pip install -r backend/requirements.txt

# 3. Configure environment
cp backend/.env.example backend/.env

# 4. Start the FastAPI backend
python -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

### Health Check Verification
With the server running, verify health connectivity:
- Browser / cURL: [http://localhost:8000/health](http://localhost:8000/health)
- Expected response: `{"status": "ok"}` with HTTP 200.
- Interactive OpenAPI Docs: [http://localhost:8000/docs](http://localhost:8000/docs)

## 6. Extension Installation and First-Run Workflow

### Loading the Extension into Google Chrome

#### Option A: Load from Source Directory
1. Open Google Chrome and navigate to `chrome://extensions`.
2. Enable the **Developer mode** toggle in the top-right corner.
3. Click the **Load unpacked** button in the top-left toolbar.
4. Browse to and select the `extension/` directory inside your cloned repository.
5. Confirm that **Why Did AI Do That?** appears with version `1.0.0`.

#### Option B: Load from Release ZIP Package
1. Unzip `WDAIDT-v1.0.0-chrome-extension.zip` into a clean folder.
2. In `chrome://extensions` with **Developer mode** enabled, click **Load unpacked**.
3. Select the folder containing `manifest.json`.

### First-Run Evaluation Walkthrough
1. Pin the **Why Did AI Do That?** icon in your Chrome toolbar.
2. Open [https://chatgpt.com](https://chatgpt.com) (or `https://chat.openai.com`).
3. Click the WDAIDT toolbar icon to open the **Chrome Side Panel**.
4. Observe the green status dot: `Backend: reachable at http://localhost:8000`.
5. Enter a prompt in ChatGPT (e.g. *"Write a quicksort in C"*).
6. Click **Why?** (or toggle **Auto** to ON).
7. Review the structured diagnostic document:
   - Examine the identified assumptions, omissions, and trade-offs.
   - Click **Copy** on the **Suggested Next Prompt** block to paste an immediate refinement back into ChatGPT.
   - Click **Copy** in the top header to export the full report as formatted Markdown.

## 7. Gemini and Mock Mode Configuration

The backend supports two operating modes via `backend/.env`:

### Zero-Configuration Mock Mode (Default)
```env
MOCK_ANALYSIS=true
```
- Operates 100% offline with zero external network requests.
- Requires no API keys and incurs zero API costs.
- Returns deterministic, realistic diagnostic documents exercising all 9 content block types.
- Ideal for offline evaluation, rapid demonstration, and hermetic automated testing.

### Live Google Gemini Analysis
```env
MOCK_ANALYSIS=false
GEMINI_API_KEY=your_actual_gemini_api_key_here
GEMINI_MODEL=gemini-3.5-flash-lite
```
- Evaluates live conversation interactions using Google Gemini (`gemini-3.5-flash-lite` with automatic fallback to `gemini-flash-latest`).
- Honest Error Handling: If `MOCK_ANALYSIS=false` and `GEMINI_API_KEY` is missing or invalid, `/analyze` responds with HTTP 502 `AI_PROVIDER_ERROR` explaining that credentials are missing. It never silently substitutes mock data for live requests.

## 9. Known Limitations

1. **ChatGPT DOM Evolution**: Content extraction uses prioritized structural and accessibility heuristics (`data-message-author-role`, `data-message-id`, `data-testid`, affordance buttons, Shadow DOM). If OpenAI releases substantial DOM overhauls, selectors may require updates.
2. **Local Server Requirement**: The Chrome Extension communicates with `http://localhost:8000`. If the local server is stopped, the extension displays a disconnected card with a **Retry** button that re-submits retained state once the server is back online.
3. **Platform Scope**: WDAIDT V1.0.0 is scoped specifically for ChatGPT web interfaces (`chatgpt.com` and `chat.openai.com`). Support for Claude or Google Gemini web interfaces is designated for future releases.
4. **Live Gemini Quota**: Live analysis requires an active Google Gemini API key with sufficient quota. Evaluators without API keys can evaluate all capabilities using hermetic Mock Mode.
