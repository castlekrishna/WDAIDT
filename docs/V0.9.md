# V0.9 — Submission Polish & Release Readiness

## Overview

WDAIDT V0.9 is the final submission polish and release-preparation milestone for **Why Did AI Do That? (WDAIDT)** prior to its V1.0 stable release. Its objective is to prepare the project for external evaluation, judges, and developers by improving submission readiness, setup clarity, interface usability, and documentation accuracy.

V0.9 maintains strict fidelity to the established architecture and scope:
- Chrome Extension Manifest V3 with side-panel architecture.
- ChatGPT prompt, response, and multi-turn context capture.
- FastAPI backend integrated with Google Gemini (`gemini-3.5-flash-lite`).
- Configurable multi-context window (`0`, `3`, `5`, `10` previous exchanges).
- Response styles, custom instructions, and analysis depth presets.
- Structured dynamic analysis documents supporting 9 validated block types.
- Obsidian pitch-black UI (`#000000`) with high-contrast typography and subtle semantic status accents.
- Epistemic modesty, anti-narration guidelines, and passive data isolation.

V0.9 expands automated regression coverage to **163 passing tests** (103 extension unit tests + 60 backend unit tests), eliminates focus-ring accessibility bugs, hardens error recovery with smart capture retry, and provides an end-to-end verified first-run evaluation experience.

## 1. Submission-Readiness Audit by Area

### A. ChatGPT Conversation Capture
- **Target Component**: `extension/src/content/chatgpt.js`
- **Audit Findings**:
  - Six-tier extraction hierarchy (`role-attributes`, `message-id` with action affordances, `conversation-turns`, `articles`, `modern-turns`, `content-blocks`) reliably extracts the latest completed user prompt and assistant response.
  - Multi-turn interactions and regenerated assistant drafts are paired correctly without stale turn retention.
  - In-progress stream states are protected: empty or actively growing assistant nodes return honest `RESPONSE_PENDING` / `paired: false` indicators rather than triggering premature analysis.
  - Non-conversation elements (toolbars, sidebars, feedback prompts, live announcements) are cleanly filtered.
- **V0.9 State**: Verified intact. Version constant updated to `0.9.0`.

### B. Multi-Context Reasoning
- **Target Components**: `extension/src/content/chatgpt.js`, `extension/src/sidepanel/app.js`, `backend/app/analysis/prompts.py`
- **Audit Findings**:
  - Configurable context window (`0`, `3`, `5`, `10` exchanges; default: `5`) functions strictly as a maximum budget, never a minimum requirement.
  - Single-turn queries with 0 prior exchanges execute cleanly without placeholders or synthetic turns.
  - Multi-turn queries accurately forward preceding turns in strict chronological order, isolated within `<CONVERSATION_HISTORY>` delimiters.
  - Total context character budget (`MAX_CONTEXT_TOTAL_CHARS = 30000` client budget / `40000` backend acceptance limit) safely prunes older complete exchanges first, never fragmenting individual turns or clipping the current prompt.
- **V0.9 State**: Verified intact.

### C. Extension-to-Backend Integration & Error Recovery
- **Target Components**: `extension/src/sidepanel/app.js`, `extension/src/shared/messages.js`, `extension/src/shared/config.js`
- **Audit Findings**:
  - `POST /analyze` accurately transmits prompt, response, context, style presets, custom instructions, and depth settings.
  - **Identified Usability Gap**: When an analysis failed due to backend unavailability or transient network timeout, the user was shown a **Retry** button. However, clicking Retry directly re-invoked `runWhy()`, which attempted to re-capture from the active tab. If the evaluator clicked into another tab, opened a new window, or shifted focus, re-capture failed with `NO_ACTIVE_TAB` or `NOT_CHATGPT_TAB`.
  - **V0.9 Resolution**: Implemented dedicated `runRetry()` workflow that retains and directly re-submits `lastCapture` with its sanitized context when available. If the service recovers, Retry succeeds immediately without requiring the user to refocus or re-scroll the ChatGPT DOM.
- **V0.9 State**: Implemented, verified, and backed by a new automated integration test.

### D. Backend Reliability & Configuration
- **Target Components**: `backend/app/main.py`, `backend/app/api/analyze.py`, `backend/app/analysis/analyzer.py`
- **Audit Findings**:
  - Python 3.10+ requirement verified against modern `google-genai` and `pydantic` v2 libraries.
  - `GET /health` returns `{"status":"ok"}` with 200 OK.
  - Input boundary enforcement: empty prompts/responses reject with 422 `INVALID_REQUEST`, payloads exceeding limits (8,000 prompt / 20,000 response / 40,000 context chars) return 413 `PAYLOAD_TOO_LARGE`.
  - Standardized error envelopes (`{"error": {"code": "...", "message": "..."}}`) for all HTTP 4xx/5xx responses.
  - Environment handling: `backend/.env` is loaded automatically from the backend directory or repository root. Mock mode is strictly opt-in (`MOCK_ANALYSIS=true`); absent API keys return an actionable 502 error rather than silent synthetic mock results.
- **V0.9 State**: Verified intact. Route documentation updated to V0.9.

### E. Analysis Quality & Epistemic Safety
- **Target Components**: `backend/app/analysis/prompts.py`, `backend/app/analysis/analyzer.py`
- **Audit Findings**:
  - System prompt rigorously enforces anti-narration (does not re-narrate lines or summarize the dialogue).
  - Diagnostic interpretations use hedged, epistemically honest phrasing ("appears to", "suggests that") without falsely claiming internal access to model weights or reasoning traces.
  - Prompt injection and untrusted conversation text are demarcated into passive XML data containers (`<CURRENT_INTERACTION>` and `<CONVERSATION_HISTORY>`).
  - Follow-up generation produces concrete, immediately actionable `next_prompt` blocks.
- **V0.9 State**: Verified intact.

### F. Obsidian UI, Usability & Accessibility
- **Target Components**: `extension/src/sidepanel/styles.css`, `extension/src/sidepanel/index.html`, `extension/src/sidepanel/app.js`
- **Audit Findings**:
  - Obsidian pitch-black aesthetic (`#000000` background, `--border-default: #303030`, `--text-primary: #F2F2F2`) preserved with zero extraneous gradients or decorative animations.
  - **Identified Accessibility Defect**: `.accordion-header:focus-visible` referenced `var(--accent-subtle)`, which was undefined in CSS `:root`, causing missing or broken focus indicators on keyboard navigation. Corrected to `var(--focus-ring)` (`#E5E5E5`).
  - **Identified Usability Defect**: When the Settings panel was opened via keyboard or mouse, pressing the `Escape` key did not dismiss the panel. Added an accessible `Escape` key event listener that closes the settings drawer and restores button state (`aria-expanded="false"`).
  - Captured Interaction card remains collapsed by default to preserve vertical real estate; full interaction text is independently scrollable without truncation.
- **V0.9 State**: Resolved and verified.

### G. Security and Privacy
- **Audit Findings**:
  - No secret keys, credentials, or sensitive test data are tracked in Git.
  - `.gitignore` rigorously excludes `.env`, `__pycache__/`, `.venv/`, `*.log`, and `node_modules/`.
  - Logging is strictly length-only (`promptLen`, `responseLen`, `contextCount`) — full prompt text is never written to disk or console.
  - CORS disables credentials (`allow_credentials=False`) while permitting `chrome-extension://` and localhost origins.
- **V0.9 State**: Fully verified.

## 3. Installation and Usability Improvements

1. **Clarified First-Run Workflow**:
   - `README.md` now provides explicit, step-by-step instructions for:
     - Environment setup via `backend/.env.example`.
     - Choosing between zero-configuration **Mock Mode** (`MOCK_ANALYSIS=true`) and **Live Gemini Mode** (`MOCK_ANALYSIS=false`).
     - Starting the FastAPI backend with both root-level (`--app-dir backend`) and directory-level commands.
     - Testing `/health` via curl or browser.
     - Loading the unpacked extension in Chrome Developer Mode.
     - Interacting with ChatGPT, opening the side panel, and performing the first analysis.
2. **Resilient Retry Workflow**:
   - If a backend request fails (server not started, transient network drop, timeout), starting the server and clicking **Retry** immediately retries the previously captured interaction without requiring tab re-selection or DOM re-capture.
3. **Enhanced Accessibility**:
   - High-contrast keyboard focus rings on the interaction accordion.
   - Standard `Escape` key shortcut to dismiss the settings drawer.

## 6. Real API Integration vs Mock Mode

- **Mock Analysis Mode (`MOCK_ANALYSIS=true`)**:
  - Deterministic, zero-cost, hermetic local evaluation.
  - Detects simple factual queries and returns clean validation without manufacturing false issues.
  - Generates diagnostic findings, underlying assumptions, and actionable follow-up prompts (`next_prompt`) for open-ended queries.
  - Transparently indicates preceding context turn count when present.
- **Live Gemini Analysis Mode (`MOCK_ANALYSIS=false`)**:
  - Configured with `gemini-3.5-flash-lite`.
  - Automatic fallback candidate list: `gemini-3.5-flash-lite` → `gemini-flash-latest`.
  - 15s timeout with automatic retry on malformed JSON outputs.
  - Live API verified in current environment: single-turn query returned title `"Enhance technical depth with a targeted follow-up prompt"`; multi-context query returned title `"Applying Embedded RAM Constraints to the Quicksort Implementation"`.

## 7. Privacy and Security Verification

1. **Credential Safety**:
   - `GEMINI_API_KEY` is loaded exclusively inside the Python backend process via `dotenv`.
   - The browser extension never receives, stores, or accesses the Gemini API key.
   - `.env` is confirmed excluded from Git tracking via `.gitignore`.
2. **Ephemeral In-Memory Processing**:
   - Prompts, responses, and context turns are processed in volatile memory only.
   - No database, vector store, or persistent interaction logs exist.
   - Structured logs record lengths only (`promptLen`, `responseLen`, `contextCount`) — zero conversation text is logged to console or disk.
3. **Passive Data Demarcation**:
   - All conversation content forwarded to Gemini is isolated within passive XML delimiters, preventing user-submitted text from overriding system instructions.

## 8. Remaining Limitations and Manual Checks

1. **Live Chrome UI Testing**:
   - Automated unit tests simulate DOM mutation and Chrome extension runtime APIs. Manual verification of the unpacked extension in Google Chrome against `https://chatgpt.com` is recommended to verify live layout compatibility against newly rolled out OpenAI DOM changes.
2. **Live Gemini Quota**:
   - When evaluating with `MOCK_ANALYSIS=false`, an active Google Gemini API key with available quota is required. Evaluators without an API key should set `MOCK_ANALYSIS=true` in `backend/.env`.
