1. System Overview

Why Did AI Do That? (WDAIDT) is a browser extension and local analysis engine that diagnoses why ChatGPT answered a prompt the way it did. It extracts visible prompt and response turns from ChatGPT, isolates them into passive XML delimiters, evaluates them using Google Gemini (or a local mock engine), and renders a structured, dynamic diagnostic report directly inside the Chrome Side Panel.

The application consists of four main pieces:

  • Content Script (extension/src/content/chatgpt.js): Lives in the ChatGPT tab, observing stream completion and extracting the prompt/response pairs without making network calls.
  • Side Panel UI (extension/src/sidepanel/app.js): Manages user preferences (tone, depth, context window), coordinates backend communication, and safely renders the 9 dynamic document blocks.
  • FastAPI Backend (backend/app/main.py & api/analyze.py): Validates payloads via Pydantic schemas, enforces character budgets, and handles standardized error envelopes.
  • Gemini Analysis Engine (backend/app/analysis/): Composes master system prompts, incorporates epistemic boundaries, calls Gemini 2.5 Flash Lite with automatic retry, and validates structured output.

3. The 3-Stop Code Tour Route

To understand the end-to-end implementation, follow these three core code locations:

Stop 1: DOM Extraction & Sanitization extension/src/content/chatgpt.js

Function: getLatestExchange() (lines 200–260)
What happens: Implements a 6-tier fallback selector hierarchy. It scans shadow DOM roots and standard articles, excludes aria-hidden elements and feedback surveys (isFeedbackOrDisclaimer), and packages the clean prompt and response pair.

Stop 2: Schema Validation & Prompt Isolation backend/app/api/analyze.py

Function: analyze_interaction() (lines 35–85)
What happens: Enforces Pydantic payload models and character budgets. Calls build_analysis_user_prompt() to wrap conversation turns inside passive XML tags (<CURRENT_INTERACTION>) before invoking Gemini or mock fallback.

Stop 3: Safe Dynamic DOM Rendering extension/src/sidepanel/app.js

Function: renderBlock() & block renderers (lines 280–420)
What happens: Dispatches each block from the API's blocks array to a specialized renderer (renderParagraph, renderCallout, renderNextPrompt, etc.). Uses pure textContent to render text safely with zero innerHTML usage.

4. "To Change This, Start Here"

Concrete starting points for customizing or extending the project:

Change default explanation depth or response style

Open extension/src/shared/config.js:

export const DEFAULT_RESPONSE_STYLE = 'Friendly and conversational';
export const DEFAULT_ANALYSIS_DEPTH = 'Brief';

Update these constants to change the initial defaults for new users.

Add a new document block type (e.g. interactive checklist)

1. In backend/app/models/analysis.py, add the Pydantic schema to BlockUnion.
2. In extension/src/sidepanel/app.js, add a renderChecklist(block) helper and register it in renderBlock().
3. In backend/app/analysis/prompts.py, document the new block type in the system prompt instructions.

Switch Google Gemini model or API configuration

Open backend/app/analysis/analyzer.py:

DEFAULT_MODEL = "gemini-2.5-flash-lite"

Adjust the model name or change timeout and retry parameters in generate_analysis_with_retry().

5. A Practice to Reuse: Epistemic Modesty & Passive Delimiters

The Architectural Practice:

When building diagnostic tools that analyze LLM outputs, never present hypotheses as omniscient truths about internal model weights. In backend/app/analysis/prompts.py, WDAIDT enforces epistemic modesty—requiring explanations to use hedged phrasing ("The response appears to prioritize...", "Given the visible constraints...").

Additionally, untrusted user inputs and conversation history are isolated inside passive XML tags (<CURRENT_INTERACTION> and <CONVERSATION_HISTORY>). This prevents prompt injection attacks where malicious conversation text attempts to override system diagnostic instructions.

6. How to Run & Try

  1. Start Backend: pip install -r backend/requirements.txt then python -m uvicorn app.main:app --app-dir backend --port 8000
  2. Load Extension: Go to chrome://extensions → Enable Developer mode → Load unpacked → Select extension/
  3. Open ChatGPT: Visit chatgpt.com, open the Side Panel, and click Why?
